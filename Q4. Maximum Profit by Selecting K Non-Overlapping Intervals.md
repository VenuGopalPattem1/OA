# Q4. Maximum Profit by Selecting K Non-Overlapping Intervals

## Problem Description

You are given `N` intervals. Each interval contains:

[startTime, endTime, profit]

You have to select **at most K intervals** such that no two selected intervals overlap.

The goal is to **maximize the total profit** of the selected intervals.

For this problem, two intervals are considered overlapping if they share an endpoint/day.

Therefore, two intervals are non-overlapping only when:

nextStart > currentEnd

Examples:

[1,2] and [2,3] → Overlapping
[2,3] and [3,4] → Overlapping
[1,2] and [3,4] → Non-overlapping
[2,3] and [4,5] → Non-overlapping

This is a **Dynamic Programming + Binary Search** problem.

## Test Case 1

Input:

events = [[1,2,4],[3,4,3],[2,3,10]]
k = 2

After sorting:

[1,2,4]
[2,3,10]
[3,4,3]

Possible valid selection:

[1,2,4] + [3,4,3] = 7

We cannot select:

[1,2,4] + [2,3,10]

because they overlap at time/day `2`.

We also cannot select:

[2,3,10] + [3,4,3]

because they overlap at time/day `3`.

Therefore the best profit is:

10

Output:

10

## Test Case 2

Input:

events = [[1,2,30],[3,4,50],[5,6,40],[2,5,100]]
k = 2

Possible selections:

[1,2,30] + [3,4,50] = 80

[1,2,30] + [5,6,40] = 70

[2,5,100] = 100

We cannot select:

[2,5,100] + [5,6,40]

because they overlap at `5`.

Therefore:

Output = 100

## Approach

First, sort all intervals by their start time.

For every interval, we have two choices:

1. Skip the current interval.
2. Take the current interval.

If we skip:

skip = fun(i + 1, k)

If we take:

take = events[i][2] + fun(nextIndex, k - 1)

Then:

dp[i][k] = max(skip, take)

The important part is finding `nextIndex`.

After selecting interval `i`, we need the first interval whose start time is strictly greater than the current interval's end time.

We use binary search to find this interval.

For example:

Current interval:

[2,3]

Next interval:

[3,4]

This is invalid because:

3 is not greater than 3.

But:

[4,5]

is valid because:

4 > 3.

Therefore our binary search condition is:

events[mid][0] > events[i][1]

## DP State

dp[i][k] means:

Maximum profit we can obtain starting from interval `i` when we can still select at most `k` intervals.

At every state:

skip = fun(i + 1, k)

next = bs(i)

take = events[i][2] + fun(next, k - 1)

Then:

dp[i][k] = max(skip, take)

## Final Solution

class Solution {
    Integer[][] dp;
    int[][] events;
    int n;

    public int maxValue(int[][] events, int k) {
        this.events = events;
        this.n = events.length;

        Arrays.sort(events, (a, b) -> Integer.compare(a[0], b[0]));

        dp = new Integer[n][k + 1];

        return fun(0, k);
    }

    public int fun(int i, int k) {
        if (i == n || k == 0) {
            return 0;
        }

        if (dp[i][k] != null) {
            return dp[i][k];
        }

        // Skip current interval
        int skip = fun(i + 1, k);

        // Take current interval
        int next = bs(i);

        int take = events[i][2] + fun(next, k - 1);

        return dp[i][k] = Math.max(skip, take);
    }

    public int bs(int i) {
        int l = i + 1;
        int h = n - 1;
        int ans = n;

        while (l <= h) {
            int mid = l + (h - l) / 2;

            if (events[mid][0] > events[i][1]) {
                ans = mid;
                h = mid - 1;
            } else {
                l = mid + 1;
            }
        }

        return ans;
    }
}

## Complexity

Let:

N = number of intervals
K = maximum number of intervals we can select

Sorting takes:

O(N log N)

There are:

O(N × K)

DP states.

Each state performs a binary search:

O(log N)

Therefore:

Time Complexity = O(N log N + N × K × log N)

This can be written as:

O(NK log N)

Space Complexity:

O(NK)

because of the DP table.

## Key Idea

The complete pattern is:

Sort intervals
→ DP(i, k)
→ Skip current interval
OR
→ Take current interval
→ Binary search for the next non-overlapping interval
→ Take the maximum profit

The most important condition for this problem is:

events[mid][0] > events[i][1]

NOT:

events[mid][0] >= events[i][1]

because touching intervals are considered overlapping.

For example:

[2,3] + [3,4] → Not allowed

[2,3] + [4,5] → Allowed
