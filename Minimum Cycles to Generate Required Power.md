# Minimum Cycles to Generate Required Power

## Problem Description

You are given N cores, where each core has a temperature stored in an integer array arr.

In one cycle, you must select exactly two unused cores i and j.

The power generated by the cycle is:

Power = |arr[i] - arr[j]|

Once a core is used in a cycle, it cannot be used again.

Your goal is to generate a total power of at least T using the minimum possible number of cycles.

Return the minimum number of cycles required.

If it is impossible to generate at least T power, return -1.


## Input

N   -> Number of cores
T   -> Minimum required power
arr -> Array containing temperatures of N cores


## Output

Return the minimum number of cycles required to generate at least T power.

Return -1 if it is impossible.


## Approach

To minimize the number of cycles, we want to generate as much power as possible in each cycle.

Sort the array.

Then pair:

smallest <-> largest
second smallest <-> second largest
third smallest <-> third largest
...

For example:

arr = [1, 3, 5, 10, 12, 15]

Pairs:

1 <-> 15
3 <-> 12
5 <-> 10

Power generated:

|1 - 15| = 14
|3 - 12| = 9
|5 - 10| = 5

We keep adding the power until:

totalPower >= T

Then return the number of cycles.

This uses a greedy approach with sorting and two pointers.


## Java Code

import java.util.*;

class Solution {

    public int minCycles(int N, long T, int[] arr) {

        // Cannot form a pair
        if (N < 2) {
            return -1;
        }

        // No power is required
        if (T <= 0) {
            return 0;
        }

        Arrays.sort(arr);

        int left = 0;
        int right = N - 1;

        long totalPower = 0;
        int cycles = 0;

        while (left < right && totalPower < T) {

            // Pair smallest with largest
            totalPower += (long) arr[right] - arr[left];

            cycles++;

            left++;
            right--;
        }

        if (totalPower >= T) {
            return cycles;
        }

        return -1;
    }
}


## Dry Run

Input:

N = 6

arr = [1, 3, 5, 10, 12, 15]


### Step 1: Sort

[1, 3, 5, 10, 12, 15]


### Cycle 1

Pair:

1 and 15

Power:

|1 - 15| = 14

Total Power = 14
Cycles = 1


### Cycle 2

Pair:

3 and 12

Power:

|3 - 12| = 9

Total Power:

14 + 9 = 23

Cycles = 2


Now:

23 >= 20

Therefore:

Answer = 2

## Edge Cases

### 1. N < 2

If there is only one core, we cannot select two cores.

Example:

arr = [10]

Answer:

-1


### 2. T = 0

If:

T = 0

No cycles are required.

Answer:

0


### 3. Impossible Target

If all available pairs together cannot generate enough power:

totalPower < T

Return:

-1


### 4. Negative Temperatures

The solution also works with negative temperatures.

Example:

arr = [-10, -2, 5, 20]

After sorting:

[-10, -2, 5, 20]

First pair:

-10 and 20

Power:

|-10 - 20| = 30


## Why Smallest With Largest?

Suppose:

a <= b <= c <= d

For two pairs, pairing opposite ends gives:

(d - a) + (c - b)

This maximizes the total difference for the selected number of pairs.

Therefore, pairing the smallest available element with the largest available element is the greedy choice.


## Complexity

O(N log N)

O(N)

Overall:

Time Complexity: O(N log N)

## Key Interview Takeaway

The main idea is:

Sort
  ↓
Use two pointers
  ↓
Pair smallest with largest
  ↓
Calculate |max - min|
  ↓
Add power
  ↓
Count the cycle
  ↓
Stop when total power >= T

The important techniques are:

Sorting + Greedy + Two Pointers

Time Complexity: O(N log N)
Space Complexity: O(1)
